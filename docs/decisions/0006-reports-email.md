# ADR 0006: Reports and email (M6)

**Status:** accepted for M6 · 2026-09-29

## Decisions

1. **One snapshot, taken in the request.** `POST /reports` runs in a REPEATABLE READ transaction. It selects approved records with the shared M4 predicate, writes a `report_item` row for each record (its revision ID plus a canonical copy of its fields), computes the metrics from those items with the domain formulas, and stores the facts. Nothing is rendered until that transaction commits. A trigger makes the snapshot columns immutable. `file_key`/`sha256` can be set only once, and an outdated report can never become current again.
2. **PDF and Excel share the snapshot.** `report.render` renders only from the stored snapshot. The Excel export for a report (`POST /exports {report_id}`) uses the same items and metrics, and there is one export per report. The dashboard's live query returns the same metrics at snapshot time (tested).
3. **Reproducible PDF** with reportlab in invariant mode. The bundled Bitstream Vera font is embedded, and every piece of text is escaped before it reaches paragraph markup. Characters the font cannot show become "?" and are counted on the last page; nothing is dropped silently. Page order follows spec §12. A render failure marks the report FAILED with no file. Retry re-renders the same snapshot, which produces the same bytes.
4. **"Outdated" means the filter no longer matches the items.** A report is current only while the approved records matching its frozen filter are exactly its items, at the same revisions. This catches corrections, archives and new records inside the filter (filter intersection, not just membership). `reports.invalidate` runs for every `production_record.changed` event. The same check also runs live when drafting, when sending and in the send worker, so an outdated report can never be sent even before the worker catches up.
5. **Summary grounding (FR17, A4).** The default is a deterministic template, and each sentence lists the fact IDs it states. The optional Claude paraphrase (`NARRATIVE_PROVIDER=claude`) receives only the facts object. It must return fact references, and it is re-validated: every number must equal a referenced fact, and cause, blame or recommendation words are refused. Any failure falls back to the template, and the reason is stored on the report. Records, operators and remarks are never sent to the model.
6. **Email is plain text, and the confirmation is a hash.** A draft's `content_hash` covers the report ID and version, the attachment checksum, the recipients, the subject and the body. Every save changes it. Send requires the draft version, If-Match and the hash the Sender saw, so an edit after preview makes the old confirmation stale (409).
7. **Commit intent, then send.** The request writes `email_message`: one per draft (UNIQUE draft_id and intent_key), with the recipients frozen. It locks the draft (trigger), queues `email.send` and returns the email ID. A double click, a replay or a concurrent request all get the same ID, so the provider is called once. The worker calls Microsoft Graph `sendMail` outside any transaction.
8. **Outcomes never overstate delivery.** 202 → ACCEPTED ("accepted by the provider; delivery not confirmed"). 429, or a request that never left, → back to QUEUED with backoff (at most 5 attempts). Read timeout, 5xx, or a worker that died mid-call (email found in SENDING) → UNKNOWN, with no automatic retry. 4xx → FAILED. 401/403 → FAILED, and the connection goes to RECONNECT_REQUIRED. A trigger allows only the valid state transitions. Recipient DELIVERED/BOUNCED require a delivery or bounce source, and none exists yet.
9. **UNKNOWN needs a person.** A Sender reconciles it with an evidence reference and a reason (audited). Until then, `RECONCILE_REQUIRED` blocks new sends for that report series and resends. A resend is always a new draft with a reason. A correction email is a new draft on a newer report version, referencing the accepted original.
10. **Attachment size.** Release 1's cap is 10 MiB, but a single Graph `sendMail` request carries at most about 3 MB of attachment inline. M6 therefore blocks attachments over 3 MiB with a clear message. Larger reports would need Graph upload sessions, which are not built.
11. **History (U8)** has one tab per kind of work (Uploads, Reports, Emails, Sync), each with its own role and department scope on the server. Filters never broaden scope.
